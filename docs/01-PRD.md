# 01 — 产品需求文档

## 产品概述
PhiTarget 是面向 Phigros 玩家的目标导向工具，不重复建设 B30/RKS 查询站。核心问题是：给定目标分数或课题铭牌，反推需要的判定、歌曲组合和个人可执行路线。

## 目标用户与场景
- 想在单曲达到指定分数、评级或判定组合的玩家。
- 想拿绿/蓝/橙/金/彩课题铭牌的玩家。
- 想冲课题等级数字、需要按个人强弱挑选三曲的玩家。
- 想研究一张谱面全部理论可达分数的玩家。

典型问题：
1. 这首歌达到 950000 需要多少 P/G？
2. 950000 是否精确可达？最近上下分数是什么？
3. 金牌且等级和至少 45，三首应该选什么？
4. 第一首打了 968000，后两首还需要多少？
5. 根据我的个人成绩，哪些组合更稳？
6. 展示某谱面全部可达分数，或只看 940000–960000。

## 产品原则
- Credential-minimal：sessionToken 只在当前页面内存中使用，不写入 PhiTarget 的存储、URL、日志或统计服务。
- Static-first：首版纯静态部署。
- No account：不要求注册或登录 PhiTarget；玩家通过已有 Phigros sessionToken 读取绑定的 TapTap 云存档。
- Explainable：推荐展示依据和安全余量。
- Version-aware：曲库、计分公式、铭牌规则带版本。
- Mobile-first：手机竖屏优先，桌面端自适应。
- Data-source agnostic：不绑定单一机器人、查分站或插件。

## P0 首发功能
### 单曲目标分数
- 普通模式 FC 控分反推。
- 普通模式指定 Max Combo 反推。
- 课题模式单曲目标分反推。
- 支持精确命中、至少达到、最接近目标。
- 显示判定组合、实际分数、目标差值和模型可信等级。

### 课题三曲组合
- 直接输入三曲课题总分，支持精确命中、至少达到、最接近目标。
- 设置难度、定数范围和章节/曲包筛选。
- 连接 TapTap 云档后，可只用已有成绩搜索组合；未连接时提供公式数量模型候选。
- 三首歌曲必须不同，同一歌曲的不同难度不作为三首独立歌曲重复计算。
- 输出 Top-K 方案，每首显示目标分、实际贡献、总分差、定数和与定数跨度。
- 公式候选标明只能作为分配参考，不宣称玩家能够实际打出。

### 曲库与规则
- 版本化曲库元数据。
- 保存 chartId、songId、难度、显示等级、定数、物量、音符类型统计、版本和课题可选状态。
- 铭牌阈值与计分规则独立配置。

## P1 玩家画像与可达性
- 通过 sessionToken 读取绑定的 TapTap 云存档。
- 显示云档中的最高成绩、近期中位数、FC/Phi 状态和存档更新时间。
- 谱面特征分组与个人强弱估计。
- 课题路线按个人数据排序。
- 课题模式可达分数集合、分桶、目标附近查询。
- 云档记录只在当前页面内存中使用，刷新后需要重新连接。

## P2 生态集成
- TapTap/云档接口适配的版本兼容与错误提示。
- 其他查分站的脱敏导出适配器（仅在格式和许可明确时加入）。
- 可选一次性导入链接或二维码（届时才需要轻量 Worker）。
- 完整谱面顺序验证。

## 当前阶段边界
当前版本提供浏览器内 B30 图片和资料卡，但不做 PhiTarget 自有账号系统或云端个人成绩库；不把 sessionToken 写入 PhiTarget 存储；不依赖机器人在线；不以谱面定数作为个人实际难度的唯一判断。B30 缺少 ACC 时会明确排除，不从普通模式总分猜测 ACC。

## 结果可信等级
- **公式可达**：仅依据计分公式和计数约束。
- **音符类型约束可达**：额外考虑哪些音符允许哪些判定。
- **谱面顺序验证**：使用完整谱面事件顺序验证连击与错误位置。

界面必须标注等级，不可将公式可达宣称为真实谱面必然可打。

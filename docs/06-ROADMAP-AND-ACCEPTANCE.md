# 06 — 开发路线与验收标准

## Phase 0：仓库与数据审计
交付：
- 当前仓库结构/框架/构建方式报告；
- 可用曲库数据源及许可证清单；
- 当前版本物量、显示等级、定数、课题可选性字段覆盖率；
- 计分公式与取整校准计划；
- UI 组件与参考图映射；
- 风险清单。

不得在审计前重写项目或批量复制第三方资源。

## Phase 1：静态基础与计分内核
交付：
- 可部署的静态应用；
- 曲库 schema 和版本加载器；
- 普通 FC 反推；
- 指定 Max Combo 计算；
- 课题单曲反推；
- 计分引擎单元测试；
- 公式说明 UI。

验收：
- 边界计数校验正确；
- P+G+B+M 必须等于 N；
- C 不得大于 N；
- FC 时 C=N；
- 公式与真实结算样本对齐，未对齐的取整规则标为待确认。

## Phase 2：课题三曲规划与救场
交付：
- 铭牌阈值选择；
- 三曲组合搜索；
- Top-K 多策略结果；
- 等级和/曲包/难度筛选；
- 已完成一首/两首后的救场计算。

当前实现：`ChallengePlanner` 已提供上述流程，并额外提供单曲课题分反推；当浏览器存在本地成绩时，个人匹配策略按每张谱面的目标分数缺口排序。

验收：
- 不允许重复同一谱面；
- 遵守当前课题模式选曲规则；
- 总分阈值上下限正确；
- 能证明方案总分达到目标；
- 不把最高等级和方案伪装成最稳方案。

## Phase 3：本地玩家画像
交付：
- JSON/CSV 导入；
- 统一内部数据模型；
- IndexedDB；
- 最高/近期/保守成绩统计；
- 个人匹配路线排序。

当前实现：`PlayerProfile` 使用 IndexedDB 保存手动和导入成绩，课题规划器可读取本地最佳成绩用于个人匹配排序；统计结果仍以描述性指标为主，不输出未经校准的成功概率。

验收：
- 不上传个人数据；
- 导入错误给出可理解原因；
- 数据源、游戏版本和更新时间可见；
- 样本不足时不输出虚假概率。

## Phase 4：可达分数分析
交付：
- 课题模式分数集合；
- 普通 FC 分数集合；
- 固定 Max Combo 的普通模式分数集合；
- 分桶、目标附近查询、代表方案和导出。

验收：
- 小物量穷举测试与优化算法结果一致；
- DP/bitset 无漏解和重复计数错误；
- 结果注明可信等级；
- 大结果不阻塞主线程。

## Phase 5：生态适配与增强
- PhiPlugin 脱敏导出文件适配；
- 其他站点导出文件适配；
- 可选 Worker 一次性导入；
- 完整谱面顺序验证；
- PWA 离线和安装体验。

## 通用验收
- 手机 360px 宽可用；
- 无服务器时全部核心功能可用；
- 玩家数据默认只在本地；
- 所有计算可复现；
- 数据版本和公式版本可见；
- 不依赖未经授权的私有 API。

# PhiTarget 分阶段实施计划

本计划按开发包中的 Phase 0–5 拆分，并以可独立验收的交付物为边界。当前仓库为空壳，因此先建立不依赖具体曲库的 TypeScript 基线。

## Phase 0：审计与项目基线（当前）

交付：

- `docs/analysis/INITIAL_AUDIT.md`：仓库、数据、许可、公式、UI 与风险审计；
- 项目目录、构建脚本、类型检查与单元测试入口；
- 版本化规则 schema 与空曲库示例；
- 第三方资料来源和许可证记录。

验收：

- 不引入虚构曲目、物量、定数或铭牌阈值；
- `core/` 不依赖 DOM、React 或浏览器 API；
- 可以在没有后端和曲库的情况下构建并运行公式测试。

## Phase 1：静态基础与计分内核

交付：

- 普通模式分数计算、FC 目标反推、固定 Max Combo 方案计算；
- 课题模式单曲目标反推；
- 有理数/整数计算、可配置取整函数和可信等级；
- 曲库与规则版本加载器；
- 公式说明页和基础响应式壳层。

验收：

- P+G+B+M=N、C≤P+G、FC 时 C=N 等边界全部拒绝非法输入；
- 小物量穷举结果与求解器一致；
- 未校准取整规则明确标为 `approximate`。

## Phase 2：课题三曲规划

交付：

- 铭牌阈值选择器（阈值来自版本化配置）；
- 候选筛选、三曲组合搜索与 Top-K 多策略结果；
- 等级和、曲包、难度范围、排除歌曲过滤；
- 单曲课题分反推。

验收：

- 不重复同一谱面；
- 能证明总分达到目标并显示余量；
- 理论最高分不足时明确标记不可达；
- “等级和最高”与“最稳”策略分别排序，不混淆含义。

## Phase 3：TapTap 玩家数据

交付：

- 使用 sessionToken 读取 TapTap 云档；
- 将 PhiHub/phi-plugin 云档映射到统一玩家成绩模型；
- best、recentMedian、recentP25、样本量、更新时间等统计。

验收：

- 不保存成绩或凭证；
- 缺少 P/G/B/M、Max Combo 或历史时间时仍能显示摘要；
- 样本不足时显示数据不足，不生成虚假胜率。

## Phase 4：可达分数分析

交付：

- 课题数量模型的分数集合与资格上限；
- 普通 FC、固定 Max Combo 的分数集合；
- 最低/最高、分桶、目标附近结果、代表方案和 CSV/JSON 导出；
- Worker 调度、取消、进度和缓存。

验收：

- 小 N 穷举与优化算法一致，无重复或漏解；
- 结果带可信等级、公式版本和曲库版本；
- 大结果不阻塞 UI。

## Phase 5：生态适配与增强

仅在数据许可和合作边界明确后实施：

- PhiPlugin 脱敏导出文件适配；
- 其他工具导出适配；
- 完整谱面顺序验证；
- PWA 离线与安装体验；
- 必要时才加入一次性导入链接或二维码 Worker。

## 当前实现顺序

1. 保留开发包文档和参考图，补充 Phase 0 审计记录；
2. 创建 `package.json`、Vite/TypeScript 配置、`src/core` 和 `tests`；
3. 实现可配置的整数计分核心与基础求解器；
4. 写边界、FC、固定 Max Combo 和课题模型测试；
5. 加入空曲库/规则 schema 与静态首页，明确数据待接入状态；
6. 运行类型检查、单元测试和生产构建，记录已知限制。

## 不在当前提交中做的事情

- 不批量下载或提交第三方曲绘/谱面包；
- 不复制 `phi-plugin` 的 GPL 代码、模板或品牌资产；
- 不硬编码未经校准的铭牌阈值为正式版本；
- 不实现 PhiTarget 自有账号、云端成绩库或机器人私有 API；sessionToken 只用于公开云档读取，不落盘。
- 不生成伪造歌曲数据来填充规划器。

# 05 — UI 设计规范

## 视觉目标
借鉴 Phigros 游戏内界面和用户提供的 PhiPlugin 截图：让 Phigros 玩家有熟悉感，同时保持简洁、现代、信息密度高、移动端易读。目标不是复刻游戏，而是提取视觉语言。

## 用户提供的参考图
- `01-phiplugin-history-timeline.jpg`：历史成绩时间线、更新时间分组、曲目卡片密集排列。
- `02-phiplugin-b30-profile.jpg`：玩家头部资料、RKS/课题数字、B30 卡片、统计图表。
- `03-phigros-result-screen.jpg`：结算页的信息层级、曲绘、成绩大数字、Max Combo、ACC、P/G/B/M。
- `04-phiplugin-push-score-suggestions.jpg`：按 ACC 区间分组的推分建议卡片。

## 视觉原则
1. 深色底色为主，使用低饱和渐变/模糊背景作为辅助，不让背景干扰文本。
2. 卡片借鉴 Phigros 的斜切、分区和强调色，但避免过多斜切导致移动端文字难读。
3. 分数、ACC、等级、铭牌余量是第一视觉层级。
4. 曲绘只作为辅助识别；没有合法可用曲绘时使用中性占位，不抓取/再分发未经许可的图片。
5. 使用 Phigros 风格的 EZ/HD/IN/AT 难度标签，但不要复制游戏字体文件或受限素材。
6. 色彩要有语义：难度、判定、铭牌、风险状态各自稳定；同时保证色盲/低对比场景可读。
7. 动效克制：数值变化、筛选展开、结果出现可有短动效；不做持续背景动画。
8. 手机优先：卡片单列或双列自适应，避免桌面式密集三列缩放到手机。

## 页面结构
### 首页/工作台
- 顶部 PhiTarget 标识、曲库版本、本地数据状态。
- 主入口：目标分数、课题规划、可达分数。
- 最近一次规划/已保存方案。
- 不做复杂仪表盘。

### 目标分数
- 模式切换：普通 / 课题。
- 搜索曲目与难度。
- 目标分数输入。
- 约束选择：FC、指定 Max Combo、允许错误范围。
- 结果区域：判定组合、分数差、可信等级、展开公式。

### 课题规划
- 铭牌选择器（自动带上下限）。
- 目标等级和、难度范围、曲包过滤。
- 玩家画像开关：不导入成绩也可运行。
- 方案卡：三首曲目、每首目标分、个人近期参考、总分、铭牌余量。
- 方案策略切换：最稳/最高等级和/均匀/个人匹配。

### 救场
- 三个槽位；录入已完成成绩。
- 自动计算剩余目标。
- 显示理论可达上限和不可达原因。

### 可达分数
- 选择歌曲/难度和模式。
- 分数范围滑块/输入框。
- 分桶图、目标附近结果、代表性判定方案。
- 高级导出。

### 玩家数据
- 导入文件、手动录入、查看数据来源与更新时间。
- 清晰说明“数据只保存在此浏览器”。
- 导出备份、删除数据。

## 组件风格
- 曲目卡：曲绘/占位 + 曲名 + 难度 + 定数/显示等级 + 物量 + 目标/历史成绩。
- 成绩卡：大分数、ACC、P/G/B/M、Max Combo。
- 课题方案卡：三首卡片组合、总分条、铭牌阈值区间、余量。
- 状态标签：公式可达、音符约束、谱面验证、数据不足。
- 图表：细线、简洁网格、避免 3D 和过度装饰。

## 设计禁区
- 不直接复制 PhiPlugin 截图的整体版式、图标、曲绘或品牌标识。
- 不将玩家信息、成绩、目标阈值堆成不可读的超密集长图。
- 不用单一颜色表达唯一状态。
- 不让渐变、模糊和装饰牺牲对比度。
- 不把 B30/查分做成首页主功能。

## UI 验收
- 360px 宽手机上主要流程无需横向滚动。
- 关键分数和铭牌阈值在一屏内可辨识。
- 长曲名、日文名、特殊字符不破坏卡片。
- 低端手机打开后不因背景动画或大图导致明显卡顿。

## PhiPlugin 开源实现可借鉴点（已检查公开 README / CHANGELOG / docs/pvis.md）

公开仓库：`https://github.com/Catrong/phi-plugin`

目前确认的实现线索：
- 插件支持 Yunzai 与 Koishi 等宿主，UI 图片通过模板/渲染器生成；README 提到 Puppeteer 与 Shotium 两种渲染路径。
- 公开 `docs/pvis.md` 描述 `.art` 模板中的文字适配：通过 `pvis` 参数给文字区域提供宽高预算、字号上下限和行高策略，再对文本进行适配。
- CHANGELOG 提到自定义主题、B30 数据分析、历史 B30、单曲成绩、推分建议、谱面六维图等功能。
- 这些信息适合借鉴“模板与数据分离、按区域约束文字、复用卡片/图表模板、主题配置”的思路。

对 PhiTarget 的建议：
1. 不需要照搬机器人图片渲染架构；PhiTarget 是交互式网页，应使用 HTML/CSS 组件和响应式布局。
2. 可以实现类似 `fitText` 的文字适配组件，专门处理长曲名、日文/特殊字符、卡片标题。
3. 将主题色、难度色、铭牌色和卡片变量抽成 design tokens。
4. 曲目卡、成绩卡、课题组合卡应复用组件，不为每个页面复制布局。
5. 先检查 phi-plugin 当前仓库的 LICENSE 与具体模板文件，再决定是否借鉴具体实现；不要复制其代码或图片作为 PhiTarget 自有资产。
